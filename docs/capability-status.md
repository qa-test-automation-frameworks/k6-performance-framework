## Feature currency review — 2026-10-16

The framework and CI pin k6 `2.0.0`. The decision below compares current code with the official
k6 documentation and v2 release notes; it does not imply that every experimental or cloud feature
is required.

| Capability                                     | Current implementation                                                                                                         | Official support checked                                                                                                                                                                                                                                                               | Benefit and compatibility risk                                                                                                                                                                  | Decision and proof                                                                                                                                                                                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Open/closed workload models                    | Typed profiles generate `constant-arrival-rate`, `ramping-arrival-rate`, `ramping-vus`, and fixed-iteration scenarios.         | [Scenario and executor reference](https://grafana.com/docs/k6/latest/using-k6/scenarios/) describes VU- and arrival-rate-driven executors, independent scenarios, tags, and timing.                                                                                                    | Keeps user journeys and arrival pressure explicit. Migration risk is workload identity and achieved-load semantics; switching executors would invalidate comparisons.                           | **Retain.** Existing executor/unit controls and the D04 controlled run `38917355038` preserve requested versus achieved rates and dropped iterations.                                                                                        |
| Endpoint thresholds and custom metrics         | Tagged endpoint p95/p99 thresholds plus custom Trend/Rate business metrics in `src/utils/metrics.ts` and `config/thresholds/`. | [Metrics](https://grafana.com/docs/k6/latest/using-k6/metrics/) and [thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/) support custom metric types and tag-scoped submetrics.                                                                                       | Separates endpoint and business behavior from the aggregate. Risk is high-cardinality tags and noisy tails; threshold/baseline changes need repeated raw evidence.                              | **Retain.** Unit fixtures reject missing endpoint metrics. D04 proves a controlled 125 ms latency injection; the separate CI run `38917355042` has seven endpoint/custom p99 breaches in one hosted sample and remains an unresolved signal. |
| Native summaries and machine-readable evidence | `handleSummary()` emits structured summaries consumed by validation and evidence adapters; k6 is pinned to `2.0.0`.            | [Custom summaries](https://grafana.com/docs/k6/latest/results-output/end-of-test/custom-summary/) documents the summary data contract; [k6 v2.0.0 release notes](https://github.com/grafana/k6/releases/tag/v2.0.0) describe the new machine-readable summary becoming the v2 default. | Avoids colored-console scraping and makes metric reconciliation possible. The v2 summary change is a compatibility boundary, so upgrades require real summary fixtures and artifact validation. | **Retain and pin.** CI checks the actual k6 version; native positive/negative evidence and D04 reports were produced on `2.0.0`. Do not claim compatibility with untested k6 majors.                                                         |
| xk6 extensions / hosted outputs                | No extension is required for current typed workloads, JSON summaries, or the existing Grafana/OTel evidence path.              | The v2 notes call out extension import-path changes; built-in output options and custom summaries cover this framework's needs.                                                                                                                                                        | An extension would add a Go build/runtime supply chain and could couple results to a hosted service.                                                                                            | **Defer.** No demonstrated gap justifies this compatibility and maintenance cost. Revisit only for a named output or protocol requirement.                                                                                                   |

This is a feature decision record, not evidence that the current baseline is universally stable. The
single-run endpoint-tail breaches remain visible until a controlled repeat study separates target,
runner, and generator noise; no thresholds or baseline values are relaxed here.

This document reports implementation and validation separately. It intentionally does not assign a
self-score.
